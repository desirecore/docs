# What is Super Document

If you have used code review, the process will feel familiar: a developer submits changes, and a colleague reviews each one before accepting or sending it back. **Super Document** applies a similar review process to documents. The Agent proposes changes; you inspect the differences and decide which to keep.

## Compared with copying an Agent's reply

| Copying a reply directly | Using Super Document |
|---|---|
| Find changes by comparing the original yourself | Additions and deletions are marked in the document |
| Copy the whole response or rewrite it | Accept or reject pending changes one by one |
| Find another copy when you need an older draft | View, compare, or restore saved versions in history |

Changes stay visible, and you decide what to keep. Saved documents can be reviewed in version history.

## When to use it

- Emails, reports, and proposals: ask the Agent to draft or revise, then inspect its changes.
- Contracts, bids, and legal documents: use the Agent to help with wording, then review each change.
- Team documents: use saved versions to review the change history.
- Knowledge notes: organize rough ideas into a document, then review the edits.

## Inspect, Review, and Save

1. Describe the writing or revision you need and wait for the Agent to finish output.
2. Inspect the document differences: red marks deletions and green marks additions.
3. Expand the review panel and accept or reject pending changes.
4. Once all pending reviews are handled, use the editor's save action or `Cmd/Ctrl + S`.

Saving is unavailable while the Agent is streaming or review items remain pending. To revise further, give the next instruction in the same conversation and review the new suggestions. See [Review Changes](./04-review-changes.md) for controls and unavailable states.

### Diff colors

**Red** marks deletions; **green** marks additions. Replacements show the removed and added text separately.
