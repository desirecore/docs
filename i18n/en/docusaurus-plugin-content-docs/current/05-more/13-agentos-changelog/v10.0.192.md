# AgentOS v10.0.192

**Release Date**: 2026-10-29

![v10.0.192 更新概览](/img/changelog/unbranded-agentos/v10.0.192-en.png)

## New Features
- **Task Board Workspace**: The current Task Board, automatic processing, flows, and relationship graph are consolidated into the Task Board workspace, leaving only the “Delegation Overview” and “Decisions” entries at the top level.
- **Structured Acceptance Criteria**: Delegators can set acceptance criteria and evidence requirements item by item when creating, delegating, and editing tasks. Executing agents self-assess each item upon submission. The acceptance panel can view the self-assessment and check unsatisfied items when sending work back for rework.
- **Agent Step Progress**: Delegation Overview cards and task details display the step progress reported by the executing agent, along with the reporting time and whether the execution has ended.
- **Workflow Human Nodes and Governed Workflows**: Workflow nodes that require human processing appear under “Awaiting Your Decision” in Delegation Overview. Task Boards can also associate with and start governed workflows, with run parameters automatically pre-filled with task references.
- **Team Archiving and Restoration**: After a team is dissolved, archived teams can be listed and restored. Agents can also view and restore team archives through team management tools.
- **Cross-Agent Archived Topic List**: Added a cross-agent list of archived manual topics, making it easier to view and restore archived topics from a unified archive entry later.
- **Task Execution and Responsibility Change Notifications**: The Task Board owner is notified when task execution ends without submission. After reassignment, transfer, or reviewer assignment, the new responsible agent or reviewing agent can be automatically awakened, and notifications can be sent again after a failure.
- **Rework Continuation Bound to Task**: Continuing a task after rework binds to the original task. When the same agent is awakened again, it continues processing or reviewing within the existing work context.
- **Decision Tree Manual Input Confirmation Optimization**: The decision tree manual answer and confirmation interface highlights the current question, supports multi-line input, optional confirm/skip, readable results, and direct selection for boolean questions.

## Fixes
- Fixed an issue where agents could not obtain a trusted draft source conversation when developing apps, preventing apps from being published to “My Apps”.
- Added support for restoring local sessions with UTF-8 byte order marks, preventing historical sessions from failing to open or being incorrectly replaced during restoration.
- Fixed an issue where streaming responses could still falsely report success after partial content had already been received, and where the model interface could still return success when there had been no new progress for a long time.
- Fixed an issue where after rebuilding a session with the same name, callbacks from old requests could affect the new session, and restoring the main session could mistakenly clear attached conversation state.
- External MCP configurations that require a higher client version now prompt for an upgrade first. Replacing a configuration preserves old options and OAuth authorization records for the same service.
- Duplicate team package imports now ask for confirmation before overwriting. When conversation records conflict, the next steps are provided instead of silently replacing existing teams and members.
- Team import no longer writes the exporter’s local trust configuration, preventing accidental trust of the exporter’s local paths, conflict markers, or local repository connections.
- Import can be canceled and clean up undelivered sources. If team import fails due to insufficient space, the original source is retained and can be retried directly.
- Closing a viewed agent webpage no longer causes it to be automatically added back by the same session. Frozen personal browser sessions with no live pages can also open a new webpage again.
- Restored the reading position of history searches and located preview matches. Native history preview preserves local media addresses to prevent images from appearing broken.
- Fixed an issue where confirming a chat screenshot on some systems caused the client to exit or left the screenshot selection area behind.
- Existing permissions are preserved when saving files. Exported PDFs preserve the Chinese text layer and monospace fonts for code.
- Canceling backup recovery releases the plaintext temporary package. The main process also cleans up recovery temporary files left by the previous abnormal exit at startup.
- Backup recovery restores workspace snapshots such as Task Boards, workflows, and whiteboards as complete objects, preserves original identities and permissions, and prevents older backups from being mixed with newer commits.
- Clarified the applicable scope of the “Allow All” approval and added explanatory notes. Fixed a race condition when switching approval modes and an ownership issue for approval settings in attached side chats.
- The startup waiting page and connection recovery page now display the application icon for the current release instead of the default icon.
- Fixed issues where activity records and execution details had duplicate pagination after filtering, empty pages could not continue loading, and “Completed Today” was silently truncated beyond 50 items.
- Fixed security vulnerabilities in underlying components such as URI parsing, and updated related dependencies accordingly.

## Improvements
- Task Board cross-board queries now use query-specific reads and yield the event loop in segments. Legacy Task Boards read only the latest commit, significantly reducing Delegation Overview load time and startup lag.
- Built-in skills written in the same batch now perform source review only once. Distribution seed content upgrades have been moved off the startup critical path, speeding up local service readiness.
- External MCP connection handling is more consistent and reduces duplicate loading within the process. Connection errors now clearly indicate the specific field issue.
- The built-in skill marketplace has been updated. Skills and scenarios such as email processing and invoice organization have been updated to the latest versions.
