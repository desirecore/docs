# AgentOS v10.0.181

**Release Date**: 2026-10-14

![v10.0.181 更新概览](/img/changelog/unbranded-agentos/v10.0.181-en.png)

## New Features
- **Application development workbench and distribution**: Agents can now create, preview, and run applications in authorized working directories, publish them to “My Applications” or the marketplace for distribution, support static web pages, native task hosts, and Docker containers as runtime modes, and provide application data, work collaboration, version history, and result review.
- **Intranet and offline distribution configuration**: Supports switching the marketplace, configuration center, Registry, and core agent sources to Gitea intranet repositories through unified configuration, and supports offline seeds, private repository reads, and backup recovery when switching fails.
- **Compact tool call prompts**: When tool processes are collapsed, directly display a summary of each operation’s action, target, and result, such as “Read file report.md” and “Calculation result: 156”, instead of only showing “Returned”.

## Fixes
- **Document read/write and file tools**: Fixed an issue where exported Word documents could not be read back and the default file access level rejected file tools, while preserving precise authorization and sensitive path restrictions.
- **Workflow parameters and approval entry**: Fixed an issue where workflow default values were masked by empty parameters, and provided a persistent pending-approval entry in long sessions that can accurately locate and focus approval cards.
- **Client and agent updates**: Fixed issues where updates could be blocked for a long time by failed marketplace preparation, certificate errors, stale scheduled launch tasks, or missing Git authentication; team upgrades and pulls now bind to the version actually approved by the user.
- **Model inference preferences**: Fixed an issue where single-turn and vision requests could send unsupported inference tiers, and where the model form and session preferences wrote back old selections.
- **MCP tool catalog freshness**: After closing an MCP connection, tool catalogs from the old source are immediately invalidated, avoiding stale tools or wrong sources continuing to appear after switching.
- **Context and tool result reachability**: Fixed issues where tool schemas kept only prefixes when the context exceeded its budget and results completed in the current turn could not be reliably pinned, and provided a paginated continuation reading method by version.
- **Document save race**: Fixed an issue where saving and closing at the same time incorrectly reported unsaved changes and where an in-flight write could not be shown as cancelable; save receipts are no longer lost when switching sessions or views.
- **Chat input focus**: Fixed an issue where automatically showing the browser session in narrow windows could steal focus from the chat input; the input box remains available during long tasks.
- **Legacy run history discovery**: Fixed an issue where old run directories lacking metadata could block new conversations; independent new conversations can now start normally, and historical files remain in place.
- **Team rules and marketplace installation**: Fixed issues including missed team rule delivery, inconsistent marketplace discovery and installation sources, inability to precisely install skills from a selected collection, and credential connections missing authorization context.
- **Mail service and spell check dictionaries**: Fixed an issue where the mail service was incorrectly reported as unavailable during the first Linux startup, and accurately show the download and readiness status of spell check dictionaries.
- **UI layering and layout**: Fixed issues where the chat model menu was covered by task overlays, vendor names in official compute announcements were shifted down and misaligned, and chat toolbar controls wrapped too early.
- **Pagination and tool parameter validation**: Strictly validate pagination parameters and tool parameters such as Grep count to avoid illegal input causing query errors or backend exceptions.
- **Terminal creation prompts**: Fixed inaccurate prompts when creating terminals by distinguishing between no available directory and directory read failure.

## Improvements
- **Model availability display**: Model availability is now displayed as an inline status dot; clicking it opens a popover with plain-language explanations and applicable actions, instead of adding an extra hint line for each model.
- **Process and reasoning display**: Thinking records in the main chat and sub-records are now consolidated into a single-layer card, collapsed by default with reading preferences remembered, and tool completion prompts are more specific.
- **Global prompt editing**: User global prompts are now loaded and edited as full Markdown text, no longer interpreted based on global heading levels; existing content will also take effect as full text after upgrade.
- **Default Python version**: The default Python version is now 3.13.9, compatible with the built-in Office runtime components, avoiding rejection when installing dependencies for the first time.
- **Startup and first installation experience**: Shortened Git preparation time during the first Windows installation, and moved the first maintenance task later to reduce waiting on the critical startup path.
- **Terminal and resource management entry**: Terminal creation prompts distinguish between missing directories and read failures, and the resource management panel now consistently opens the workspace terminal tab corresponding to the current session.
