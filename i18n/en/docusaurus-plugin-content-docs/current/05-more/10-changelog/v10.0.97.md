# DesireCore v10.0.97

**Release Date**: 2026-07-29

## New Features
- **Queued message visualization**: Messages sent during streaming output now appear as a queue list above the input box. You can edit, delete, intervene (inject as a steer into the current turn), or abort the current output to send that message instead — no more blindly optimistic insertion into the chat flow.
- **One session now supports two concurrent streams**: Within the same session, user messages and background incoming messages or delegation reports can happen simultaneously. Streaming output no longer mixes text between them, and stop / continue actions apply only to the user’s own turn.
- **Dynamic busy-state display in the Agent list**: In the sidebar, People list, and resource panel, busy Agents now show a dynamic `›››` flowing indicator and real-time activity text (e.g. “Using Bash”), automatically restoring to normal when the task finishes.
- **Numeric badges on terminal tabs**: When holding Cmd / Ctrl, the terminal tab bar displays corresponding numeric badges so you can see which number key to press for quick switching.
- **Prevent computer sleep while tasks are in progress**: A new Power Settings section has been added, with the master switch enabled by default — when an Agent is running a task, a terminal is active, or the app is downloading updates, the system is automatically prevented from entering idle sleep, releasing the hold immediately once tasks finish.
- **Agents can independently clone and manage team repositories**: ManageAgent adds clone actions; ManageTeam adds query / pull / push / fork actions. Team repository git-rule prompts are introduced, completing the Agent’s closed-loop capabilities in team collaboration.
- **Allow deletion of an Agent’s default working directory**: The default system working directory can now be deleted, allowing you to configure an agent to work only inside user-specified project directories. Fallback safety for paths when no working directory is set has also been tightened.
- **Background-update completion pop-up reminder**: When choosing “Background update”, a global persistent desktop toast appears after the download completes, informing you that the update is ready and providing a “Restart Now” button.
- **Differentiated sub-agent status bar**: The status bar at the top-right of the chat area is now split into two semantically correct groups — “Delegated Agents” (real avatars) and “Sub-Agents” (temporary sub-tasks). The collapsed capsule also displays a three-segment count.
- **SendMessage incoming messages now show the sender**: Messages sent by other Agents now appear in the target chat in real time, correctly displaying the sender’s avatar and name — no longer silently swallowed or only shown after switching away and back.
- **Runtime environment adds GitHub CLI detection**: A `gh` (GitHub CLI) installation detection card is now displayed on the Compute Settings – Runtime Environment page.

## Fixes
- **The `running` state no longer permanently locks a session**: When an Agent query unexpectedly gets stuck, the session is no longer forever blocked from sending new messages. The system now automatically reclaims the zombie running state after 5 minutes and allows you to continue the conversation in place.
- **Queued messages no longer disappear from the UI after stopping generation**: When you send a new message during streaming output and then click stop, queued message bubbles are now correctly preserved and eventually sent instead of being mistakenly discarded due to snapshot timing deviations.
- **The first message after clearing chat history is no longer overwritten**: A message sent immediately after clearing the chat now correctly merges with the greeting and is no longer silently hidden by the greeting fully overwriting it.
- **Aborting and rapid consecutive sends no longer create two concurrent queries**: Fixed a potential issue where a message sent shortly after stopping generation could bypass the queue and create dual concurrency with an in-flight query. A session-level dispatch gate ensures only a single query is in progress at any time.
- **Agent prompts created by tools are no longer persisted as raw JSON**: When creating an agent via ManageAgent, its `persona.md` is now correctly saved as structured Markdown instead of a bare JSON string; system prompts no longer lose structural semantics and become ineffective.
- **Submit button is no longer “falsely disabled” in multi-question scenarios**: After answering the current question when unanswered ones remain, the submit button changes to an enabled orange “Go answer →” button, and previous / next question navigation arrows are added, so you no longer feel stuck by a gray disabled state.
- **Delegation / async tasks now correctly show a failure state after failing**: When a delegated sub-task fails (e.g. due to model errors), its card now displays a red “Failed” terminal state rather than sticking on “Processing” or being misjudged as “Completed”.
- **The pause button no longer breaks due to event propagation**: Clicking pause no longer leaks the event object into the socket payload, which previously caused a stack overflow; pause now works stably.
- **Messages are no longer lost when the target run is still executing**: When encountering “The selected history branch is still running”, messages no longer vanish completely. They are returned to the queue list and automatically re-sent when the terminal event fires.
- **Context management (ManageContext) no longer breaks topic bookkeeping and recall**: Fixed 11 defects including missing messages in `messageRange` after reset, discarded replies during archival, garbled recall information, and inconsistent context boundaries. Reset semantics are now anchor-based.
- **Canvas windows are now isolated per session**: When multiple agents concurrently use Canvas (HTML rendering / screenshots), each now has its own independent window — pages and screenshots no longer overwrite each other across sessions.
- **Fixed missing ordered / unordered list markers in Markdown**: Ordered and unordered list markers in chat bubbles, notification previews, and email bodies now display correctly.
- **Windows upgrades add integrity verification for native modules**: After upgrading, detection of whether native module files (such as `sharp` and `node-pty`) have been fully written is more reliable, preventing launch crashes caused by security software interception and a false “upgrade complete” report.
- **Videos no longer turn into broken images after restart**: Fixed an issue where tool-generated videos played correctly the first time but became unplayable after restarting the app because the media type was incorrectly locked to “image”. Existing persisted data is automatically corrected during rendering.
- **Follow-up question cards no longer burst the input box**: Multi-question follow-up cards now have a maximum height (44vh / 420px). Overflowing question areas are scrollable, while the title bar and submit bar remain always visible instead of pushing the entire window out.
- **Slash command panel no longer incorrectly triggers after a mid-sentence space**: Typing a slash after a space in the middle of a sentence (e.g. `2: /`) no longer opens the command panel; the trigger is now strictly limited to the very beginning of the input box.
- **Badge silently refreshes after marking notifications as read**: After marking notifications as read or an Agent rewrites notification files, the foreground unread badge and notification center now update in real time without needing an app restart.
- **Agent errors are now visible to the Agent itself**: When an Agent inspects history via tools such as InspectRuns, it can now see accurate records that include failure markers, error codes, and interruption hints — no longer misreading failed turns as successful completions.
- **Terminal background made opaque**: Fixed an issue where the semi-transparent background of the terminal content area caused contrast-calculation distortion and made some ANSI colors nearly invisible in light mode. The full ANSI 16-color palette and `COLORFGBG` injection have also been added.
- **Unified fix for the “Open in File Manager” function of working directories**: Multiple working-directory entry points — the input box capsule, environment status widget, resource panel, and more — now all correctly open the file manager and show an error prompt when necessary.

## Improvements
- **Team repository git protection refactored**: Moved from intercepting terminal command text to Git protocol-layer hardening and environment variable injection, combined with prompt-driven self-audit guidance, reducing false blocks on normal Bash operations while improving protection coverage.
- **Built-in skills are now loaded before ManageAgent lifecycle operations**: Before create / update / delete, the corresponding built-in skill must be loaded to obtain complete operational guidance, preventing steps like requirement gathering and security confirmation from being skipped.
- **Enhanced incremental context management**: Pin now supports snapshot retention across boundaries; discard results maintain the correct state after refresh; compression, retraction, reset, and other context operations are more reliable.
- **Unified terminal viewport**: All terminals — including background terminals, cold terminals, and hidden agent terminals — now follow the panel’s uniform size, no longer causing TUI layout misalignment when switching tabs or due to initial size mismatches.
- **Friendlier continuation status text**: The activity badge and button now replace blunt wording like “Continue (length)” with “Processing” and downplay the specific reason.
- **Unified working-directory open and error prompts**: The “Open Folder” functionality across four working-directory UIs now uses a common entry point, with clear toast prompts on failure.
- **Clarified SendMessage reporting semantics**: The `notify_only` and `wait` parameters now explicitly declare whether the report should start a turn on the recipient’s side and whether to wait for a reply — no longer left to code inference.
- **Inbound queries are now sibling runs**: Queries sent by other Agents no longer pre-empt the user’s current session run; instead they create an independent sibling run within the same session, avoiding transcription mix-ins and context interference.
- **Optimized greeting display and run ownership**: The merge logic between the greeting and the user’s first message after clearing the chat is more robust, fixing a series of race conditions including `runId` overwrites and streaming index shifts.
- **Improved push-message wrapping, ordering, and offline backfill**: Enhanced content-signature matching for multi-segment messages, index ordering across machine clock skew, and backfill attribution, making the message timeline more stable and consistent.
