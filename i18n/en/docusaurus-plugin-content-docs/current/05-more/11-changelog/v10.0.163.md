# DesireCore v10.0.163

**Release Date**: 2026-09-15

![v10.0.163 更新概览](/img/changelog/v10.0.163-en.png)

DesireCore v10.0.163

## New Features
- **Built-in browser explicit takeover and conversation recovery**: The built-in browser adds an explicit “Let me operate” takeover entry point. Once the user starts a new conversation turn, the Agent can continue execution through the conversation, no longer relying on a manual resume button.
- **1Password credential source integration**: The account management page adds a 1Password source, supporting connecting, browsing, and associating entries. You can search and select entries to copy into the built-in credential vault; after import, they are decoupled from subsequent 1Password changes.
- **Multi-instance catalog v2**: The instance selector now lists instances based on authoritative per-instance records. Deleting an instance that is running or has an unknown state is rejected with a reason.
- **Claude subscription UI context availability**: Claude subscription sessions can now view UI snapshots and, within the same turn, declare and call UI view and action tools.
- **Damo Academy Solver distribution (OEM)**: Added distribution-specific branding, data directory, update channel, and reporting. On first launch, it automatically provisions solver agents, teams, connector configurations, and a decision workspace.
- **OEM distribution parallel installation on Linux**: Non-default distributions now share a unified Linux desktop identity and can be installed alongside the default DesireCore, with desktop entries and taskbar groups not overwriting each other.

## Fixes
- Fixed an issue where user identity was not restored promptly after a cold start, causing users who selected a browser space they owned to be misidentified as external users and receive a 403 error.
- Fixed an issue where macOS packaging did not correctly write privacy permission declarations into Info.plist, which could cause access to the camera, microphone, contacts, and other resources to be denied or terminated by the system.
- Fixed an issue where multiple processes concurrently installing the same system cache utility could produce corrupted binaries or fail to install.
- Fixed a security vulnerability where managed credentials and solver connector credentials could be indirectly read by the Agent through placeholders, skill connection injection, workflow templates, and similar paths, and closed a race window in credential reference registration.
- Fixed an issue where the approval card did not show the connector and address to which credentials would be sent when MindOptSolve initiated a solve.
- Fixed an issue where the model could not see or execute UI actions when the chat page had history, and where the UI context access reference was lost when sending from the input box.
- Fixed an issue where, after a distribution locked its branding, interfaces such as conversation bubbles, history, search, and notifications still displayed the default brand name and greeting.
- Fixed an issue where intelligent routing, when switching models after consecutive 529 errors, could carry a local token and connect directly to the upstream, bypassing proxy and audit.
- Fixed an issue where readers could occasionally falsely report record corruption during concurrent fork-for-resend publishing.

## Improvements
- The schema validation worker now precompiles built-in descriptor schemas during startup to avoid false validation timeouts on high-load machines.
