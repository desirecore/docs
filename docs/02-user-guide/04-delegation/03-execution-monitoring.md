# 执行监控

计划写入后，智能体会按你的自然语言指示继续、暂停或修改执行。你可以实时监控进展，并在需要时随时介入；不需要先操作一个统一的“批准计划”状态。较新的 DesireCore 会在长任务确实需要责任分派、阻塞跟踪、跨智能体协作或持续可见进度时使用悬浮任务板。

## 执行过程的实时展示

任务执行时，你会看到一个实时更新的进度面板：

![执行监控面板](/img/user-guide/delegation/execution-monitoring.svg)

### 步骤状态标识

| 状态 | 图标 | 含义 |
|------|------|------|
| 待办 | 🔹 | 任务已创建但还未开始 |
| 等待中 | ⏳ | 队列排队等待（依赖未完成或前序步骤未结束） |
| 执行中 | 🔄 | 正在处理 |
| 已完成 | ✅ | 步骤成功执行 |
| 需确认 | 🚪 | 人闸门，等待你的确认 |
| 警告 | ⚠️ | 执行成功但发现问题 |
| 失败 | ❌ | 执行失败 |
| 已放弃 | 🗑️ | 任务被丢弃（已软删除，仍可在审计记录里查到） |

## 任务清单（让进度对你透明）

任务清单不是 Plan 的状态机，也不会机械复制 Plan 的每一步。只有当工作需要明确负责人、记录阻塞、协调多个智能体，或需要持续展示关键进度时，智能体才把相应工作项挂到自己的「任务清单」上。简单顺序仍以 Plan 文件为准。你随时可以问“现在到哪一步了”“还剩什么”。

### 任务清单的样子

每条任务都有明确的标题、状态、关联信息：

```
📋 任务清单（智能体「合同审查助手」）

🔄 #1 解析合同文件，提取关键条款
        进行中 · 关联 .desirecore/plans/<plan-id>/PLAN.md

🔹 #2 检查违约金比例
        待办 · 依赖 #1 完成

🔹 #3 检查付款条件
        待办 · 依赖 #1 完成

🔹 #4 分析进口设备条款（灵活）
        待办 · 风险:中 · 依赖 #1 #2 #3 完成

🔹 #5 综合风险评估（灵活）
        待办 · 风险:中 · 需要你确认

🔹 #6 发送审查报告
        待办 · 风险:高 · 需要你确认
```

### 状态表示什么

| 状态 | 含义 | 你可以做什么 |
|---|---|---|
| 待开始 | 工作尚未开始 | 核对负责人和前置任务 |
| 进行中 | 正在处理 | 查看最近更新和阶段成果 |
| 阻塞 | 缺少输入、权限或前置结果 | 查看原因，补充所缺信息 |
| 待确认 | 成果已提交，等待验收 | 打开成果，确认或要求修改 |
| 已完成 | 任务已按规则完成 | 核对最终交付物 |
| 失败 | 执行未能完成 | 查看错误和已有成果，再决定重试 |

状态由智能体和任务板维护，不代表每条后台命令的实时状态。长时间没有更新时，可询问进度，或到任务管理器查看执行是否仍在运行。

### 任务之间的依赖关系

任务可以声明"做我之前要先做某某"。比如"运行数据库迁移"必须依赖"备份完成"先成功——智能体看到依赖未完成时不会去执行后续步骤，避免顺序错乱。

依赖关系会在清单里显示为「依赖 #X 完成」，你能一眼看出整个任务图的执行顺序。

### 偏离计划时清单会同步更新

如果智能体在执行中发现需要调整步骤，它会：

1. 主动告诉你"打算偏离原计划，原因是 X"
2. 通过自然对话吸收你的意见；如果你明确要求先确认，它会等待，否则更新相关任务项
3. 把偏离记录追加到计划文件末尾的 `## Execution Notes` 小节

这样事后看 plan 文件 + 任务清单，能完整还原"实际怎么做的"。

### 当前对话与全局任务板

聊天中的任务清单方便查看当前工作的进度。跨对话或多人协作时，打开左侧导航的“全局任务板”，按任务板或负责人查看任务。能查看和修改哪些任务，取决于任务板权限；同一团队也需要按负责人和审核规则协作。

登记任务不会自动开始执行。完整步骤见 [长耗时任务](./07-long-running-tasks.md)。

## 悬浮任务板

当智能体把任务拆成多个子任务时，聊天区会出现悬浮任务板。任务板展示智能体通过任务工具维护的进度记录。

任务板通常显示：

- 当前任务标题和整体进度
- 每个子任务的状态，如待开始、进行中、已完成或失败
- 优先级、负责人、依赖关系和更新时间
- 当前正在执行的任务和失败原因

它适合跟踪代码修改、资料调研、文档批量处理和跨智能体协作等长任务。

:::tip 与工作流卡片的区别
工作流卡片展示智能体计划中的步骤；任务板展示运行中不断更新的任务状态。一个任务可能先有计划，再在执行过程中被拆成更多任务。
:::

## 固化步骤与灵活步骤

执行步骤可包含按规则完成的工作，也可包含 AI 判断。查看执行记录时，留意步骤的类型和结果依据。

### 固化步骤（Deterministic Step）

- **特点**：规则明确，结果确定
- **执行方式**：像程序一样精确执行
- **可预测性**：执行 100 次，100 次结果相同
- **示例**：检查数值是否超过阈值、提取特定字段、格式转换

```
⚙️ [固化] 检查违约金比例
  规则：违约金 ≤ 20% → 合规
  输入：合同第 8 条，违约金 = 15%
  结果：✅ 合规（15% ≤ 20%）
```

### 灵活步骤（Adaptive Step）

- **特点**：需要 AI 理解和判断
- **执行方式**：基于上下文推理
- **可预测性**：不同的输入可能有不同的推理路径
- **示例**：分析合同语义、评估综合风险、生成报告

```
🧠 [灵活] 分析进口设备条款
  依据：合同第 12-15 条内容
  推理过程：
    - 第 12 条提到"进口设备"但未指定原产国
    - 第 13 条有安装验收条款但未提及中文说明书
    - 根据已学规则：进口设备必须有中文说明书条款
  结果：⚠️ 缺少中文说明书条款，建议补充
```

:::info 验收时检查什么
固化步骤按既定规则执行，但输入、规则或环境仍可能有问题。灵活步骤还包含 AI 判断。验收时都应检查结果；涉及判断的步骤，应同时核对依据。
:::

## 暂停和继续执行

| 你想做什么 | 操作 | 接下来检查什么 |
|---|---|---|
| 中断当前执行 | 使用当前运行的停止操作，或告诉智能体暂停 | 到任务管理器确认后台命令是否仍在运行 |
| 继续未完成的工作 | 告诉智能体先核对计划和已有成果，再继续 | 已完成的步骤、未完成的步骤和仍在运行的命令 |
| 重试失败步骤 | 先查看失败原因，再要求重试 | 文件是否已写入、外部请求是否已提交，避免重复 |
| 回撤本地变更 | 打开 [Rewind 与 Checkpoint](../02-conversations/10-rewind-checkpoints.md) | 检查点包含哪些文件，以及将恢复什么内容 |

停止当前执行不保证取消外部服务已接收的请求。重试、跳过或继续的方式取决于具体任务；并非每项操作都能从中断处自动接着执行。

## 执行中的异常处理

工作流面板也会显示运行级失败提示，包括节点开始前发生的启动或连接错误。没有某个失败节点，不代表运行成功；查看顶部的失败原因，并在核对已完成动作后决定重连或重试。

当智能体遇到问题时，它会根据情况采取不同的处理方式：

### 自动重试

对于网络超时等暂时性错误，智能体会自动重试：

```
⚠️ 步骤 4 执行失败：文件读取超时
   自动重试中... (第 1/3 次)
   ✅ 重试成功
```

### 主动上报

对于无法自行解决的问题，智能体会主动告诉你：

```
智能体："步骤 4 遇到了问题：

        ⚠️ 合同文件中第 13 条引用了一个附件（附件 C：设备规格书），
        但我没有找到这个附件。

        请选择：
        1. 提供附件 C 的文件
        2. 跳过此步骤，在报告中标注'缺少附件 C'
        3. 暂停任务，我稍后处理"
```

### 执行中插入新指令

你随时可以在执行过程中给智能体补充指令：

```
你："等一下，第 12 条的保密期限也要特别关注，
    如果超过 5 年标记为风险。"

智能体："收到，我会在后续步骤中增加保密期限的检查。
        当前步骤不受影响，将在步骤 5（综合评估）中纳入。"
```

如果任务正在运行，你也可以使用 `/steer` 发送方向调整。它会作为运行中的 steer 指令进入当前任务，不会像重新发送普通消息那样开启新任务。

## 委派任务的审批与等待

子智能体执行命令或工具时可能触发审批。DesireCore 会把审批请求和最终决策同时显示在子智能体会话，并**镜像到发起委派的父智能体会话**；系统通知也优先指向父会话，因此你无需为了批准操作来回切换面板。

| 审批模式 | 委派中的等待行为 |
|---|---|
| **AI 审批** | 你可在 30 秒内决定；到时按 AI 建议自动批准/拒绝，没有建议则拒绝 |
| **每次确认 / 白名单未命中 / 外部工具审批** | 持续等待真人决定，不因普通审批倒计时自动拒绝 |
| **全部放行** | 普通确认被跳过，但拒绝列表、文件范围和工具权限仍生效 |

同步委派本身有独立的等待上限。若父智能体先收到“等待超时”，这不表示子任务已经终止：子任务可能仍在后台执行或等待你的审批。超时提示会附带可用的任务引用；父智能体可以继续等待、忽略后续结果，或在支持时主动结束该子任务。

## 回撤执行状态

如果你发现智能体已经沿着错误方向执行了一段时间，优先使用 [Rewind 与 Checkpoint](../conversations/rewind-checkpoints)。Rewind 会基于检查点恢复对话和工作状态，而不是只在进度面板中“回滚某一步”。
