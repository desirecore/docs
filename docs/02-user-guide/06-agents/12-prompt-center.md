# 提示词中心与内容归属

:::info 长期指令的版本支持
`instructions.md` 已在开发分支的 10.0.179 实现。截至 2026-10-09，最新公开发行版仍为 v10.0.177；正式发行版需要升级到包含这项能力的版本后才能使用。
:::

提示词中心把分散在用户、团队和智能体目录中的提示词来源放到同一个界面中管理。打开 **资源管理器 → 提示词中心**，左侧选择作用范围，右侧编辑内容或预览组合结果。

## 三个作用范围

| 作用范围 | 影响范围 | 内容 |
|---|---|---|
| **全局** | 当前用户的所有智能体 | 用户通用偏好、工作方式和跨智能体规则 |
| **团队** | 该团队的全部成员和组长；属于多个团队时可出现多段 | 团队协作约定、共享术语和交付标准 |
| **Agent** | 单个智能体 | `persona.md` 角色与表达、`principles.md` 边界与优先级、可选 `instructions.md` 长期职责与交付要求 |

在支持长期指令的版本中，运行时按 **全局 → 团队 → Agent 人格 → Agent 行为准则 → Agent 长期指令** 组合可编辑片段，再加入团队身份、工具、Skill、记忆和会话等运行时上下文。团队提示词不能伪造或改写真实团队身份；成员、组长和同伴关系来自团队配置。项目规则应保留在项目工作目录的 `AGENTS.md` 等文件中。

## 分层文件的 L0 / L1 / L2

全局和团队编辑器支持表单与 Markdown 源码两种模式；人格和原则也支持分层 Markdown。分层时必须使用严格的二级标题：

```md
## L0
一句话核心摘要

## L1
- 每次任务都需要看到的关键要点

## L2
较长的背景、示例和例外
```

| 层级 | 运行时行为 |
|---|---|
| **L0** | 注入系统提示词 |
| **L1** | 默认注入系统提示词 |
| **L2** | 默认不注入，保留为按需读取的详情 |

L0/L1/L2 表示加载粒度，不是权限或安全等级。分层文件没有可识别的层级标题时，会整份作为一个提示词片段加载；全局和团队编辑器可能提示格式问题。

## 长期指令使用普通 Markdown

`instructions.md` 不使用上述加载层级，不要求或解析 frontmatter。它保存这个 Agent 稳定的职责、默认工作策略和交付标准。正文中写了 `## L2` 也不会按需隐藏这一段：获准加载时，整份正文进入独立提示词片段，不摘要、不截断。全文超出上下文预算时会明确失败；把详细方法、长 SOP 和参考资料放入技能，而不是为长期指令编写摘要层。

保存后的内容在新的输入、显式继续或恢复被接纳时刷新；同一执行轮次保持快照。普通心跳全文加载，`lightContext=true` 的轻量心跳跳过它。完整格式和工具更新约定见[文件格式说明](../../05-more/06-file-formats.md)。

## 编辑和预览

1. 选择“全局提示词”、某个团队，或展开某个智能体
2. 分层文件按其编辑器填写 L0/L1/L2 或 Markdown；Agent 的“长期指令 instructions”直接编辑完整 Markdown
3. 保存内容
4. 对 Agent 选择“提示词预览”，按全局、团队、Agent 和系统分组检查组合结果

预览会显示片段来源和字符数，适合发现重复、冲突和过长内容。预览反映查询时可加载的静态上下文；实际请求还可能动态加入 inbox、handoff、语音、工具或最新团队状态，因此排查实际请求时应以接口审计记录为最终依据。长期指令只是动态系统提示词的一个来源，不保存或替换完整 `systemPrompt`。

## 写作建议

- 全局只写用户对所有智能体的通用要求，团队写协作约定；个人和项目内容不要复制到可共享的 Agent 本体
- 人格写角色和表达方式，原则写边界和优先级，长期指令写稳定职责、默认策略和交付标准
- 分层文件把每次需要的内容放在 L0/L1；长期指令全文加载，详细方法转到技能和参考资料
- 不要依靠提示词替代工具权限和审批策略

## 实战示例

例如，文档工程师可以按归属保存以下内容，避免把每项要求都塞进人格：

| 归属 | 示例 |
|------|------|
| 用户全局提示词 | 用户偏好中文回复，技术术语保留英文原文 |
| 团队提示词 | 文档团队采用统一术语和文档格式 |
| `persona.md` | 技术文档工程师，表达简洁、准确，面向开发者 |
| `principles.md` | 不把未验证的能力写成已实现；不编造来源 |
| `instructions.md` | 交付可操作的说明、必要示例与验证结果；标明已验证和待确认的边界 |
| 技能与参考资料 | 构建、断链检查、图片目录和发布流程的详细步骤 |

## 常见问题

| 问题 | 原因与解决 |
|------|-----------|
| 分层文件保存后关键内容没生效 | L2 默认不注入；确认每次需要的规则在 L0/L1 中 |
| 长期指令保存后当前任务仍使用旧内容 | 当前执行轮次保留快照，在新的输入、显式继续或恢复接纳时读取新内容 |
| 预览中看到重复内容 | 同一要求写到了多个作用范围；保留在真正归属的位置 |
| 团队提示词不生效 | 确认智能体已加入该团队；多团队时检查对应来源 |
| 分层源码提示格式问题 | 检查标题是否严格为 `## L0`、`## L1`、`## L2`；长期指令无需这些标题 |
| 找不到长期指令入口 | 检查客户端是否已包含 10.0.179 开发分支中的长期指令能力 |
| 长期指令超出预算 | 精简正文，把详细步骤移到技能；它不会通过截断或 L2 隐藏来继续执行 |

:::caution 提示词 ≠ 权限
修改提示词不会改变智能体的工具权限、文件访问范围或审批策略。如需调整权限，请使用相应权限设置。
:::
