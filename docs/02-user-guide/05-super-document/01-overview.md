# 超级文书是什么

用过 Code Review 吗？开发者提交代码后，同事逐项检查改动，再决定接受还是退回。**超级文书（Super Document）**把类似的审阅方式用于文档：智能体提出修改，你查看差异并决定保留哪些内容。

## 与直接复制智能体回复相比

| 直接复制回复 | 使用超级文书 |
|---|---|
| 自己对照原文查找改动 | 文档中直接标出新增和删除 |
| 整段复制或重新改写 | 逐项接受或拒绝待审阅修改 |
| 想回到旧稿时另找备份 | 在版本历史中查看、比较或恢复已保存的版本 |

修改可见，是否保留由你决定。保存后的文档可以在版本历史中查看。

## 适合哪些文档任务

- 邮件、报告或方案：让智能体起草或润色，再检查改动。
- 合同、标书或法律文件：让智能体协助整理文字，由你逐项审阅。
- 团队文档：通过已保存的版本查看修改记录。
- 知识整理：把零散想法整理成文档，再逐项确认。

## 查看、审阅和保存

1. 提出写作或修改要求，等待智能体输出完成。
2. 查看文档差异：红色表示删除，绿色表示新增。
3. 展开审阅面板，接受或拒绝待审阅修改。
4. 待审阅项处理完后，使用编辑器保存入口或 `Cmd/Ctrl + S` 保存。

智能体仍在输出或有待审阅项时，保存暂不可用。需要继续调整内容时，在同一对话中说明修改要求，再审阅下一轮建议。具体按钮和状态处理见[逐条审阅](./04-review-changes.md)。

### 差异颜色

**红色**表示删除，**绿色**表示新增。替换内容会分别显示被删文字和新增文字。
