# 应用、插件与服务

应用是相对独立的软件或工作台；插件是补充 DesireCore 平台能力的应用子类；服务是 MCP、HTTP 等连接和执行接口。三者有关联，但不是同一种使用入口。

## 从哪里进入

| 我要做什么 | 入口与动作 |
|---|---|
| 使用已安装应用 | 主导航“应用” → “应用”页签，选择应用并打开 |
| 配置平台插件 | 主导航“应用” → “插件”页签，查看接入状态、启停贡献和调整配置 |
| 获取新的应用或插件 | 市场 → 应用分类；插件可用“产品类型：插件”筛选 |
| 管理服务连接和运行问题 | 资源 → 服务，查看连接、配置与诊断 |

应用与插件处于同一个工作区的同级页签。切换页签保留已访问视图，不混合应用的“打开”与插件的“启用、配置、停用”。从其它面板进入插件设置，仍保留原来源的返回入口。

插件安装完成只说明安装事实；能否接入还取决于配置、兼容性、依赖和使用权限。插件页会展示实际接入结果；“已启用”不代替当前运行证据。无已安装插件时会显示空态，可点击“发现插件”进入市场筛选。

## 目录里有什么

| 条目 | 说明 |
|------|------|
| 应用 | 可打开和使用的独立软件或工作台 |
| 插件 | 向 DesireCore 平台贡献能力的应用子类，在插件页签配置与管理 |
| 服务 | 应用安装后注册出的 MCP、HTTP 或本地服务 |
| 待审批项 | 服务注册、调用、提权或测试连接时需要你确认的请求 |
| 安装记录 | 已安装、失败、运行中、已停止、可更新等状态 |

## 安装流程

1. 在市场中选择应用或插件
2. 点击「安装」并选择目标设备，DesireCore 委派核心智能体执行安装
3. 在委派会话或任务中查看安装进度；智能体核验结果后登记实例
4. 从“应用”页签打开应用；插件进入“插件”页签查看贡献及接入条件
5. 需要连接 MCP 或 HTTP 服务时，按服务接入流程单独配置和授权
6. 能否启用插件或调用服务，由当前配置、兼容性和使用权限决定

应用的打开与维护、插件的贡献启停，以及服务的连接与运行状态分别管理；安装一项不会自动授权另一项。任务取消、发送失败或智能体中断时，先核对实际目标与安装记录，再决定是否重试。

有些兼容安装条目会提供已声明的服务，但并非每个应用都有服务。服务实际接入和使用权限在对应资源中核验，安装不自动授予调用权限。

安装完成后，打开条目详情查看可用操作，例如启动、停止、重启或更新。

安装失败时，打开详情查看原因和日志。界面提供「重试」时，再决定是否重新安装。

## 服务审批

服务请求访问资源或执行操作时，会显示待审批项。打开请求详情，核对来源和权限，再决定是否批准。

| 请求 | 你需要核对什么 | 风险等级 |
|----------|----------|----------|
| 注册服务 | 应用要连接哪个服务、用途是什么 | 低 |
| 调用外部接口 | 要访问哪个第三方服务 | 中 |
| 访问本地文件或端口 | 要读取或修改哪些本地资源 | 中 |
| 申请更高权限 | 为什么需要额外权限，影响哪些操作 | 高 |
| 健康检查 | 服务会检查什么状态 | 低 |

这些操作遵循当前审批模式和具体权限。需要确认时，你可以批准、拒绝或查看详情；安装、启用和实际调用各自检查授权。

:::tip 授权与关联
应用关联、插件启用或服务连接不能替代实际使用权限。共享工作区只改变入口与布局，不扩大智能体的可调用范围。
:::

## 状态与排障

常见状态包括：

| 状态 | 含义 | 下一步 |
|------|------|------|
| Installed | 已安装，不一定正在运行 | 打开详情查看可用操作 |
| Running | 服务正在运行 | 不可调用时检查审批和健康状态 |
| Stopped | 已停止 | 需要使用时，在详情中查看启动操作 |
| Failed | 安装或启动失败 | 查看错误摘要和日志，再决定是否重试 |
| Update available | 有可用更新 | 打开详情，选择「更新」 |
| Pending approval | 等待你审批 | 前往待审批面板查看并处理请求 |

## 常见问题

**Q: 安装的应用在目录中找不到？**

先确认查看的是“应用”还是“插件”页签，并检查目标设备与当前连接实例。再查看原委派任务的核验及登记结果；目录或登记缺失不证明软件不存在，不要直接重复安装。

**Q: 服务显示 Running 但智能体说无法调用？**

服务正在运行不等于当前智能体有使用权限。检查连接、当前智能体可用工具与审批状态；需要确认的操作通过已有审批流程处理。

**Q: 为什么同一个应用有多条安装记录？**

安装记录按来源和目标设备分别管理。请在详情中核对这两项，再对正确的实例执行更新或卸载。

**Q: 如何更新已安装的应用？**

从对应管理入口请求更新，智能体读取当前实例与维护材料，核验版本、配置和数据保留范围后执行。更新失败后的实际状态应重新检查，不承诺任意软件更新都能自动回滚。

**Q: 卸载应用会影响已产生的数据吗？**

卸载针对精确安装实例，先检查共享使用者和数据影响；默认保留用户数据。插件停用只撤销其贡献，不自动卸载应用或清理数据；需要清理时另行明确范围。
