# 应用与服务目录

应用与服务目录把第三方应用、MCP 服务和由应用派生的本地服务集中管理。它不只是一个列表，而是从安装、注册、审批到启停更新的闭环。

## 打开目录

在 DesireCore 界面中进入应用与服务目录：

- **桌面端**：左侧导航栏 → 底部齿轮图标「设置」→ 「应用与服务」标签页
- **快捷方式**：对话中提到安装应用时，智能体会自动打开对应页面

目录首页分为三个区域：

| 区域 | 内容 |
|------|------|
| 应用列表 | 已安装和可安装的第三方能力包 |
| 服务面板 | 各应用注册出的 MCP / HTTP / 本地服务及其运行状态 |
| 审批队列 | 需要你确认的权限请求（角标数字提示） |

## 目录里有什么

| 条目 | 说明 |
|------|------|
| 应用 | 可安装的第三方能力包或集成入口 |
| 服务 | 应用安装后注册出的 MCP、HTTP 或本地服务 |
| 待审批项 | 服务注册、调用、提权或测试连接时需要你确认的请求 |
| 安装记录 | 已安装、失败、运行中、已停止、可更新等状态 |

## 安装流程

1. 在 Marketplace 或应用目录中选择应用
2. 点击「安装」按钮（或让智能体在对话中执行安装）
3. DesireCore 委派核心智能体执行安装脚本
4. 安装记录写回本地（可在安装记录中查看历史）
5. 应用派生的服务被 watcher 自动发现并注册
6. 需要权限的服务进入待审批面板（角标提示）
7. 审批通过后，服务变为可用状态

安装完成后，你可以从目录中对应用/服务执行：

- **启动 / 停止 / 重启**：控制服务运行状态
- **更新**：检测到新版本时一键升级
- **卸载**：移除应用及其注册的服务
- **查看详情**：查看健康状态、日志摘要、配置信息

:::tip 通过对话安装
你也可以直接对智能体说："帮我安装 XXX 应用"，智能体会自动完成安装流程并报告结果。
:::

## 服务审批

服务可能请求以下操作：

- 注册新服务
- 调用外部 API
- 访问本地文件或端口
- 提升权限
- 执行健康探测

这些请求会进入审批流程。你可以批准、拒绝或查看详情。未经审批的 stdio 服务不会被后台静默执行。

## 状态与排障

常见状态包括：

| 状态 | 含义 |
|------|------|
| Installed | 已安装但不一定运行中 |
| Running | 服务正在运行 |
| Stopped | 已停止 |
| Failed | 安装或启动失败 |
| Update available | 有可用更新 |
| Pending approval | 等待你审批 |

如果服务不可用，可以先查看详情页中的健康检查结果、日志摘要和审批状态。

## 常见问题

**Q：安装后服务一直显示 Pending approval？**

服务注册后需要你在审批队列中点击「批准」。未审批的 stdio 服务不会在后台静默运行——这是安全设计。进入「应用与服务」→ 审批队列，找到对应请求并批准即可。

**Q：服务状态显示 Failed，如何排查？**

1. 点击服务条目 → 查看「日志摘要」获取错误信息
2. 检查依赖是否就绪（如 Docker 是否运行、端口是否被占用）
3. 尝试「重启」服务
4. 若仍失败，卸载后重新安装

**Q：更新后服务行为异常？**

部分更新需要重新审批权限。检查审批队列是否有新请求。如果更新引入了 breaking change，查看服务详情页的更新日志。

**Q：如何查看哪些智能体在使用某个服务？**

在服务详情页的「调用记录」中可以看到近期调用该服务的智能体和任务摘要。

**Q：可以同时运行多个同类服务吗？**

可以。每个应用实例独立注册，通过服务 ID 区分。在智能体的 MCP 配置中选择需要连接的具体服务实例。
