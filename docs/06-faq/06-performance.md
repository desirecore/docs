# 性能问题

## 应用占用过多内存？

DesireCore 桌面客户端会占用一定的基础内存。如果内存占用异常偏高：

1. **检查版本** --- 确保你使用的是最新版本，开发团队会持续优化性能
2. **检查智能体数量** --- 同时运行超过 300 个智能体会显著增加内存开销
3. **关闭不用的对话** --- 每个活跃对话会占用独立的上下文缓存
4. **重启应用** --- 长时间运行后内存可能逐渐增长，定期重启可以释放累积的内存

## AI 回复的响应速度慢？

响应速度主要取决于 AI 模型 API 的性能，与 DesireCore 客户端本身关系较小。优化建议：

| 因素 | 优化方法 |
|------|---------|
| 模型选择 | 简单任务使用轻量模型（如 GPT-5-nano、DeepSeek-V3） |
| 上下文过长 | 定期清除不需要的对话上下文 |
| 网络延迟 | 选择地理位置更近的 Provider 端点 |
| 工具调用 | 不需要工具时明确告知 Companion |
| 供应商负载 | 高峰时段更换 Provider 或等待 |

## 磁盘占用过大？

DesireCore 的数据存储在 `~/.desirecore/` 目录。磁盘占用增长的主要来源：

| 来源 | 典型大小 | 清理方法 |
|------|---------|---------|
| 运行记录 (`runs/`) | 随使用时间增长 | 设置 > 数据与隐私 > 清除本地数据 > 对话记录 |
| 市场缓存 (`market/`) | 数百 MB | 可安全删除，会自动重建 |
| 缓存与日志 (`cache/`, `logs/`) | 数十~数百 MB | 可安全删除，会自动重建 |
| 智能体仓库 (`agents/`) | 每个数 MB | 删除不需要的智能体 |

:::tip 快速释放空间
最安全的做法：关闭 DesireCore → 删除 `~/.desirecore/cache/` 和 `~/.desirecore/logs/` → 重新启动。这不会影响任何智能体数据和配置。
:::

## GPU 占用高或风扇狂转？

DesireCore 使用 GPU 加速渲染界面（玻璃材质、动画效果）。如果 GPU 占用异常：

1. **检查显卡驱动** --- 确保使用最新的显卡驱动
2. **减少窗口数量** --- 关闭不需要的 DesireCore 窗口
3. **禁用硬件加速** --- 以 `--disable-gpu` 参数启动应用
4. **检查其他 GPU 程序** --- 确认是否有其他程序（游戏、视频编辑）同时占用 GPU

:::info
在低功耗模式下，DesireCore 会自动降低渲染帧率以减少 GPU 和电池消耗。
:::

## 长时间运行后变慢？

如果 DesireCore 运行数天后明显变慢：

1. **重启应用** --- 最直接有效的方法，释放累积的内存和缓存
2. **检查后台任务** --- 大量定时调度或心跳任务可能占用资源
3. **清理过期运行记录** --- 历史回执过多会影响索引速度
4. **检查系统资源** --- 打开任务管理器/活动监视器确认 CPU、内存、磁盘 I/O 是否饱和

## 如何查看 DesireCore 的资源占用？

| 平台 | 方法 |
|------|------|
| **macOS** | 打开「活动监视器」，搜索 "DesireCore" 或 "desirecore" |
| **Windows** | 打开「任务管理器」(Ctrl+Shift+Esc)，在进程列表中查找 |
| **Linux** | 终端运行 `ps aux \| grep desirecore` 或使用 `htop` |

DesireCore 包含多个进程（主进程、渲染进程、Agent Service），这是正常的 Electron 架构。

## 大量智能体同时在线会影响性能吗？

会。每个在线智能体维护独立的运行上下文和心跳连接：

| 在线智能体数 | 预期影响 |
|-------------|---------|
| < 20 | 几乎无感知 |
| 20 - 100 | 内存增加，启动时间略长 |
| 100 - 300 | 明显内存增长，建议关闭不活跃的 |
| > 300 | 不推荐，显著影响响应速度 |

:::tip
不需要使用的智能体可以设为离线状态。在对话头部点击状态指示器即可关闭。
:::
